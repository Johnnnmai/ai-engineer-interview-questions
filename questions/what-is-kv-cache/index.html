What the interviewer is testing

Whether you understand autoregressive decoding well enough to explain what is cached and why, can estimate memory with the formula, and know that the cache, not only the weights, often limits batch size and context length.

Answer framework

  1. State the reason: during autoregressive decoding the keys and values of earlier tokens do not change.
  2. State the saving: store and reuse them, so each new token computes only its own Q, K and V instead of recomputing the whole prefix.
  3. State the cost: memory per sequence is roughly 2 x layers x kv_heads x head_dim x tokens x bytes per value.
  4. State the consequence: it often limits batch size and context length more than the weights do.
  5. Name the mitigations: grouped-query attention, KV quantization and paged allocation (as in vLLM's PagedAttention).

Sample answer

During autoregressive decoding the keys and values of earlier tokens do not change, so they are stored and reused; each new token computes only its own query, key and value. That turns per-step attention from recomputing the whole prefix into one pass over cached tensors.

The trade-off is memory. Per sequence it is roughly 2 x layers x kv_heads x head_dim x tokens x bytes per value. For a 32-layer model with 8 KV heads, head_dim 128, 8k tokens in fp16 that is 2 x 32 x 8 x 128 x 8192 x 2 bytes, about 1 GiB per sequence. That is why the KV cache often limits batch size and context length more than the weights do.

Grouped-query attention, KV quantization and paged allocation, as in vLLM's PagedAttention, exist to shrink or pack it.

Likely follow-ups

Estimate KV-cache memory for a 32-layer model, 8 KV heads, head_dim 128, 8k tokens, fp16. 2 x 32 x 8 x 128 x 8192 x 2 bytes, about 1 GiB per sequence.

Common mistakes

  • Saying queries are cached; only keys and values of earlier tokens are reused.
  • Describing the speed benefit without the memory cost.
  • Assuming model weights are the only memory constraint when serving long contexts or large batches.
  • Not being able to do the back-of-envelope memory estimate.
  • Confusing the KV cache with response caching or prompt caching for shared prefixes, which are application-level cost levers.
