Explain LoRA and QLoRA

How to answer it in an AI engineer interview: what is being tested, a step-by-step framework, a sample answer and the mistakes to avoid.

What the interviewer is testing

Whether you know the mechanism (a frozen base plus a learned low-rank update), why it is cheap, what QLoRA adds, and the practical choices: rank, alpha, target modules and how to spot overfitting.

Answer framework

  1. LoRA: freeze the base weights and learn a low-rank update W + BA for selected matrices, with small rank r (often 8 to 64).
  2. Why it is cheap: trainable parameters drop by orders of magnitude, adapters are small files, and several adapters can share one base model.
  3. QLoRA: keep the frozen base in 4-bit and train LoRA adapters on top, so large models can be fine-tuned on a single GPU.
  4. Practical choices: learning rate, epochs, rank r and alpha, target modules, batch size and sequence length.
  5. Watch for overfitting: falling training loss with flat or rising validation loss; stop early and keep the best checkpoint.

Sample answer

LoRA freezes the base weights and learns a low-rank update for selected matrices: W + BA, where A and B have a small rank r, often 8 to 64. Trainable parameters drop by orders of magnitude, adapters are small files, and several adapters can share one base model.

QLoRA keeps the frozen base in 4-bit and trains LoRA adapters on top, which makes fine-tuning of large models feasible on a single GPU.

The hyperparameters that matter most are learning rate, number of epochs, rank r and alpha, which modules get adapters, batch size and sequence length. I apply LoRA to the attention projections at minimum; adding the MLP layers usually helps quality at more cost. If training loss falls while validation loss is flat or rising, I stop early and keep the best checkpoint.

Likely follow-ups

Which layers do you apply LoRA to? Attention projections at minimum; adding MLP layers usually helps quality at more cost.
What is quantization and why does it matter for deployment? Storing weights in fewer bits, for example 8-bit or 4-bit instead of 16-bit. It cuts memory roughly 2x to 4x; re-run task evals because degradation is uneven.

Common mistakes

  • Saying LoRA updates all the weights, or that it changes the base model file.
  • Confusing QLoRA (a 4-bit frozen base during training) with quantizing a model for serving.
  • Not knowing which modules to target or what rank and alpha control.
  • Ignoring validation loss and training until the adapter overfits.
  • Treating fine-tuning as the way to add frequently changing facts; retrieval is better for that.
