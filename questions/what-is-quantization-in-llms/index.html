What is LLM quantization and why does it matter for deployment?

How to answer it in an AI engineer interview: what is being tested, a step-by-step framework, a sample answer and the mistakes to avoid.

What the interviewer is testing

Whether you can explain why fewer bits help serving (memory and bandwidth), name the common methods, and show the engineering discipline of checking quality on your own tasks afterwards.

Answer framework

  1. Define it: store weights, and sometimes activations or the KV cache, in fewer bits, such as 8-bit or 4-bit integers instead of 16-bit floats.
  2. Memory: roughly 2x smaller at 8-bit and 4x smaller at 4-bit for the weights.
  3. Speed: decoding is usually memory-bandwidth bound, so moving fewer bytes per token often raises throughput.
  4. Methods: post-training quantization such as GPTQ and AWQ keeps quality loss small at 4-bit for many models; QLoRA uses 4-bit weights for fine-tuning.
  5. Risk: quality loss is uneven, often showing first in math, code and long-context tasks, so re-run your evals.

Sample answer

Quantization means representing model weights with fewer bits. A 7-billion-parameter model in 16-bit needs about 14 GB just for weights; at 4-bit that drops to roughly 3.5 GB plus some overhead for scales. That can be the difference between needing a large GPU and fitting on a smaller one, or between one replica and several per GPU.

It often speeds things up too. During decoding each new token requires reading the weights from memory, so the step is usually limited by memory bandwidth rather than arithmetic. Fewer bytes per weight means more tokens per second, especially at small batch sizes.

For post-training quantization I would start with an established method such as AWQ or GPTQ at 4-bit, or 8-bit if quality is critical, and quantize the KV cache if long contexts are the bottleneck. Then I re-run our task evals, not just a general benchmark, because degradation is uneven: arithmetic, code and long-context retrieval tend to suffer first.

Likely follow-ups

Weight-only vs weight-and-activation quantization? Weight-only cuts memory and helps bandwidth-bound decoding; quantizing activations too can speed up compute-bound prefill but is harder to do without quality loss.

Common mistakes

  • Claiming quantization has no quality cost.
  • Checking only perplexity or a public benchmark instead of task evals.
  • Forgetting the KV cache, which can dominate memory at long context.
  • Assuming 4-bit is always faster; it depends on kernels and hardware support.
