考察点

能否准确定义 agent（模型在循环中选择下一步动作），说出什么时候不该用，并表明你知道安全运行一个 agent 需要什么。

评分要点

  1. chain 是开发者定义好的固定步骤序列；agent 是一个循环，由模型根据观察结果选择下一步动作（调用哪个工具、传什么参数），直到它判断任务完成。
  2. 说出模式：ReAct 在推理、工具调用和读取观察结果之间交替。
  3. 决策规则：能画出流程图就做 workflow（工作流）；路径取决于无法穷举的中间结果时才用 agent。
  4. 生产意识：步数上限、超时、预算、参数校验、不可逆操作需人工批准、完整 trace、按任务成功率评估。

常见扣分点

把任何多步骤的 LLM 流水线都叫作 agent。

参考回答

Chain 是开发者定义好的固定步骤序列。Agent 是一个循环：模型根据观察结果选择下一步动作，也就是调用哪个工具、用什么参数，直到它判断任务完成。常见模式是 ReAct：模型在推理、工具调用和读取观察结果之间交替。

Agent 能处理开放式任务，但可预测性更差。如果我能画出流程图，我就做一个内部调用模型的 workflow，因为它更便宜、可测试、可预测。很多好系统都是只含一个 agent 步骤的 workflow。

在生产环境里，我会给 agent 设最大步数、超时和单任务预算，校验每个工具参数，对瞬时错误做退避重试，保存状态 checkpoint，不可逆操作要求人工批准，并记录完整 trace。评估时看一组固定的真实任务上的成功率，以及步数、成本和延迟，并检查执行轨迹，而不只看结果。

常见追问

Workflow 和 agent 怎么选？ 能画出流程图就做 workflow。当路径取决于无法穷举的中间结果时，再用 agent。
