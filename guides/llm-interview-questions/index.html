Architecture questions

  • Question: Explain the transformer architecture. Answer: a stack of layers, each with self-attention and a feed-forward network, plus residual connections and normalization, introduced in >Attention Is All You Need. Decoder-only models predict the next token with a causal mask. Deep dive: transformer architecture.
  • Question: What does self-attention compute? Answer: each token builds a query, key and value; attention weights come from query and key similarity, and the output is a weighted sum of values. Multiple heads let the model attend to different patterns at once.
  • Question: Why does long context cost more? Answer: standard attention compares every token with every other token, so compute grows roughly with the square of sequence length, and the KV cache grows linearly with it. See what is a context window.
  • Question: What is mixture of experts? Answer: a layer with several expert networks and a router that sends each token to a few of them, so total parameters grow while compute per token stays lower. See mixture of experts.
  • Question: What are scaling laws? Answer: empirical relationships between model size, data and compute and the resulting loss, described in >Kaplan et al., 2020 and revisited for compute-optimal training in >Hoffmann et al., 2022. See scaling laws.

Tokens and decoding questions

  • Question: What is tokenization and why does it matter? Answer: text is split into subword tokens from a fixed vocabulary. It affects cost, context limits, multilingual quality and odd failures such as character counting. See tokenization in LLMs.
  • Question: Temperature vs top-p? Answer: temperature rescales the probability distribution, lower is more deterministic; top-p, or nucleus sampling from >Holtzman et al., samples only from the smallest set of tokens whose probability adds up to p. Change one at a time. See temperature vs top-p.
  • Question: Why can the same prompt give different answers? Answer: sampling randomness, and sometimes nondeterminism in serving. Use low temperature, fixed seeds where offered and structured output when you need consistency.
  • Question: How do you get reliable structured output? Answer: schema-constrained output where the API supports it, validation, and retry with the error message. See reliable JSON output.
  • Question: What is chain-of-thought prompting? Answer: asking the model to reason step by step before answering, which improved multi-step reasoning in >Wei et al., 2022. See chain-of-thought prompting.

Training and adaptation questions

  • Question: Pre-training vs instruction tuning vs RLHF? Answer: pre-training learns language from large text corpora; instruction tuning teaches the model to follow tasks; preference tuning such as RLHF, used in >InstructGPT, aligns outputs with human preferences. See pre-training vs instruction tuning vs RLHF.
  • Question: What are LoRA and QLoRA? Answer: >LoRA freezes base weights and trains small low-rank matrices; QLoRA does this on a quantized base model to save memory. See LoRA and QLoRA.
  • Question: When would you fine-tune instead of prompting or RAG? Answer: when you need consistent format, style or a narrow skill that prompting cannot reach, and you have quality examples. For missing knowledge, use retrieval. See RAG vs fine-tuning.
  • Question: How do you build a fine-tuning dataset? Answer: collect real task examples, write consistent target outputs, remove duplicates and sensitive data, hold out an evaluation split and track data versions. See building a fine-tuning dataset.
  • Question: Reasoning models vs chat models? Answer: reasoning models spend more tokens thinking before answering, which helps multi-step problems but adds latency and cost. Route only hard tasks to them. See reasoning vs chat models.

Behavior, risk and evaluation questions

  • Question: Why do LLMs hallucinate? Answer: they are trained to produce likely text, not verified facts, so gaps in knowledge or ambiguous prompts can yield fluent but wrong answers. Mitigate with retrieval, citations, abstention and checks. See why LLMs hallucinate.
  • Question: What is prompt injection? Answer: input that overrides the system's instructions, directly from the user or indirectly through retrieved content. Treat untrusted text as data and limit tool permissions. See prompt injection.
  • Question: How do you evaluate an LLM for your product? Answer: define the task, build a representative labeled set, pick metrics per failure type, compare against a baseline and combine automated checks with human review. See the LLM evaluation interview questions guide.
  • Question: What is benchmark contamination? Answer: test data leaking into training data, which inflates scores. Prefer private or fresh evaluation sets. See benchmark contamination.
  • Question: What is lost in the middle? Answer: models tend to use information at the start and end of long inputs better than in the middle, so order and trim context carefully. See lost in the middle.

Serving and cost questions

  • Question: What is the KV cache? Answer: stored keys and values from earlier tokens so each new token does not recompute them. It speeds generation but uses memory that grows with context and batch size. See KV cache.
  • Question: What is quantization? Answer: storing weights, and sometimes activations, in fewer bits to cut memory and speed up inference, with some quality risk that you measure on your task. See quantization in LLMs.
  • Question: How do you reduce LLM latency? Answer: stream tokens, shorten prompts, cache, use a smaller model where quality allows, and batch on the server. See reducing LLM latency.
  • Question: How do you reduce inference cost? Answer: route easy requests to cheaper models, cache, trim context, cap output length and measure cost per successful task. Price scenarios with the free LLM API cost calculator.
  • Question: Embedding model vs generative model? Answer: an embedding model maps text to vectors for search and clustering; a generative model produces text. They are trained and served differently. See embedding vs generative models.

FAQ

  • What LLM topics come up most in interviews? As general guidance, transformers and attention, tokenization and decoding, fine-tuning vs RAG, hallucination, evaluation and serving cost come up often in AI engineer loops.
  • Do I need to derive attention math? Usually you need to explain it clearly and know why it scales with sequence length. Research roles may ask for more depth.
  • How much should I know about training? Know the stages, what each changes and when you would fine-tune. Most AI engineer roles focus on adapting and serving models rather than pre-training them.
  • Are LLM interview questions different from AI engineer interview questions? LLM questions are a subset focused on how models work. AI engineer loops add coding, RAG, agents, system design and behavioral rounds.
