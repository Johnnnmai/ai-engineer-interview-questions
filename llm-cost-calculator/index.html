How the math works

  1. Uncached input cost = input tokens × (1 − cache share) × input price ÷ 1,000,000.
  2. Cached input cost = input tokens × cache share × cached-input price ÷ 1,000,000.
  3. Output cost = output tokens × output price ÷ 1,000,000.
  4. Per day = cost per request × requests per day. Per month = per day × 30.

Worked example: GPT-6.1 Terra at $1.00 input and $5.00 output per 1M tokens, 2,000 input and 500 output tokens, 10,000 requests a day, no caching. Per request is 2,000 × 1.00 ÷ 1M + 500 × 5.00 ÷ 1M = $0.0045. Per day is $45.00 and per month is $1,350.00.

How to explain cost trade-offs in an interview

Cost questions show up in LLM system design rounds as soon as you propose a model. Interviewers want to see that you can turn a design into a number and then defend the levers you would pull.

  1. State the unit economics. Tokens in, tokens out, price per million, requests per day. Say the monthly number out loud.
  2. Find the biggest term. Long system prompts and retrieved context usually dominate input; long answers or reasoning dominate output.
  3. Pull the cheapest lever first. Prompt caching for repeated prefixes, shorter retrieved context, capped output length.
  4. Route by difficulty. Send easy requests to a small model and escalate hard ones, and say how you would measure that quality holds.
  5. Name the risk. Every saving trades something: freshness for caching, accuracy for a smaller model, latency for batching.

Questions

Where do the prices come from? Each price was read on Nov 1, 2026 from the provider's own pricing page, linked in the sources table on this page. Prices change often, so check the provider page before you commit to a budget.
How is the monthly cost calculated? Cost per request is input tokens times the input price plus output tokens times the output price, divided by one million. With caching on, the cached share of input tokens is billed at the cached-input price. Daily cost is cost per request times requests per day, and monthly cost is daily cost times 30.
What does the cache-hit toggle do? It bills a share of your input tokens at the provider's published cached-input or cache-hit price. Set the share to how much of each prompt is a repeated prefix, such as a long system prompt or shared documents. Cache-write premiums and cache storage fees are not included.
Does it include batch discounts or off-peak rates? No. The calculator uses standard on-demand rates. Batch APIs and DeepSeek off-peak hours are cheaper, and the notes under each source say by how much where the page states it.
Why are long prompts more expensive on some models? Some providers charge a higher rate once a single request passes a context threshold, for example 272K input tokens on several OpenAI models and 200K on some Gemini models. The calculator switches to those rates automatically when your input tokens pass the threshold.
How do I use this in an interview? Show the unit economics first: tokens per request, price per million tokens, requests per day. Then name the levers that change the number, such as a smaller model for easy requests, prompt caching and shorter outputs, and say what each one risks for quality.
