  1. Deconstruct the question. Identify the core concept or problem being asked.
  2. Define key terms. Clearly explain any technical jargon or specific algorithms mentioned.

Fundamentals of Vector Databases

1. What is a vector database and why is it used in AI/ML?

  • A specialized database designed to store, manage, and query high-dimensional vectors.
  • Vectors represent embeddings generated from data like text, images, or audio using ML models.
  • Enables efficient similarity search, finding items that are semantically similar to a query vector.
  • Crucial for applications like recommendation systems, semantic search, and anomaly detection.

Common pitfall: Describing it as just a key-value store or failing to mention embeddings and similarity search.

2. Explain the concept of vector embeddings.

  • Numerical representations of data (text, images, etc.) in a high-dimensional space.
  • Generated by embedding models, capturing semantic meaning and relationships.
  • Similar items have vectors that are close to each other in the vector space.
  • The dimensionality and quality of embeddings depend heavily on the chosen embedding model.

Common pitfall: Confusing embeddings with raw data or failing to mention their generation by ML models.

3. What are distance metrics and why are they important for vector search?

  • Functions used to quantify the similarity or dissimilarity between two vectors.
  • Common metrics include Cosine Similarity and Euclidean Distance (L2). Dot Product is an inner-product similarity measure; if used as a distance, it typically requires transformation (e.g., negation).
  • The choice of metric depends on the nature of the embeddings and the desired similarity notion.
  • Affects the ordering of search results and the performance of indexing algorithms.

Common pitfall: Listing metrics without explaining their purpose or how they relate to vector closeness.

4. What is Approximate Nearest Neighbor (ANN) search?

  • A technique to find vectors that are *approximately* closest to a query vector, rather than exactly.
  • Trades perfect accuracy for significant improvements in search speed and scalability.
  • Essential for handling large datasets where exact k-NN search is computationally infeasible.
  • Relies on specialized indexing structures to prune the search space.

Common pitfall: Not highlighting the accuracy-performance trade-off or its necessity for large-scale systems.

ANN Indexing Strategies

5. Describe HNSW (Hierarchical Navigable Small Worlds) indexing.

  • Builds a multi-layered graph where each layer is a sparse graph, with higher layers being sparser.
  • Search starts at the top layer and greedily navigates towards the query vector.
  • Offers a good balance between search speed, recall, and index build time.
  • Key parameters like `efConstruction` and `M` control the trade-off between build quality and speed. `efSearch` controls the search time vs. recall trade-off.

Common pitfall: Failing to explain the hierarchical nature or the graph traversal search mechanism.

6. Explain IVF (Inverted File Index) indexing.

  • Partitions the vector space into `k` clusters (centroids) using a clustering algorithm like k-means.
  • During search, it identifies relevant clusters and only searches within those partitions.
  • Performance depends on the number of clusters (`nlist`) and the search scope (`nprobe`).
  • Recall can degrade when reducing the number of probes (nprobe) for faster searches, not directly because of speed.
  • Often combined with product quantization (IVF-PQ) for memory efficiency.

Common pitfall: Not mentioning the initial clustering step or the `nlist` and `nprobe` parameters.

7. What is Product Quantization (PQ)?

  • A compression technique that divides vectors into sub-vectors and quantizes each sub-vector independently.
  • Reduces memory footprint significantly by representing vectors with shorter codes.
  • PQ compresses the stored vectors themselves, not the cluster centroids; centroids remain in full precision. Its primary benefit is vector compression.
  • It is often used in conjunction with IVF (IVF-PQ) to reduce the memory required for storing the compressed vectors.
  • Introduces some loss of precision due to quantization.

Common pitfall: Describing it as a standalone indexing method without mentioning its compression role or combination with IVF.

8. Compare and contrast HNSW and IVF indexing.

  • HNSW builds a graph structure, while IVF partitions the space into clusters.
  • HNSW generally offers higher recall at low latencies but can have higher memory usage.
  • IVF is often more memory-efficient, especially when combined with PQ, but recall can degrade when reducing the number of probes (nprobe) for faster searches, not directly because of speed.
  • Index build times can vary; HNSW can be slower to build for very large datasets.

Common pitfall: Not clearly stating the primary difference in their underlying data structures (graph vs. partitioning).

9. Discuss newer ANN algorithms like ScaNN and DiskANN, and other libraries like Faiss, Annoy, and HNSWlib.

  • ScaNN (Scalable Nearest Neighbors) centers on anisotropic vector quantization plus partitioning and rescoring (Guo et al. 2020), not asymmetric hashing.
  • DiskANN is optimized for memory-constrained environments, allowing indexes to be larger than RAM by efficiently accessing data from disk.
  • Faiss (Facebook AI Similarity Search) is a popular library offering highly optimized similarity search algorithms, including IVF and HNSW, with GPU acceleration.
  • Annoy (Approximate Nearest Neighbors Oh Yeah) uses random projection trees for indexing, known for its simplicity and memory efficiency.
  • HNSWlib is a C++ library specifically for the HNSW algorithm, providing efficient implementations.
  • Trade-offs involve complexity, build times, memory/disk usage, recall-latency curves, and support for features like GPU acceleration and dynamic indexing.

Common pitfall: Not being able to articulate the core innovation or primary use case for each algorithm or library.

Operational Considerations and Advanced Features

10. How does metadata filtering work with vector search?

  • Allows combining vector similarity search with traditional attribute-based filtering (e.g., category, date).
  • Metadata is stored alongside vectors and can be applied either before vector search (pre-filter) or after retrieving candidates (post-filter), depending on the engine, to prevent misunderstanding of the execution order.
  • A concrete example of pre-filter vs. post-filter: Pre-filtering might involve selecting only documents tagged 'news' before performing vector search, while post-filtering would retrieve top-k similar documents and then filter out those not tagged 'news'.
  • Can significantly improve relevance by narrowing down the search to specific subsets of data.
  • Performance implications depend on index structure and filter selectivity.

Common pitfall: Assuming filtering happens only after vector search or not explaining its impact on relevance.

11. What are the challenges with updates and deletes in vector databases?

  • ANN indexes are often built offline and are not designed for frequent modifications.
  • Updates/deletes can require rebuilding parts or all of the index, impacting availability and performance.
  • Some systems use techniques like journaling or background indexing to mitigate these issues.
  • Trade-offs exist between index freshness, query performance, and modification overhead.

Common pitfall: Suggesting updates/deletes are as seamless as in traditional relational databases.

12. Explain sharding in the context of vector databases.

  • Distributing data (vectors and metadata) across multiple nodes or shards.
  • Enables horizontal scalability to handle massive datasets and high query loads.
  • Requires a strategy for routing queries to the correct shards and aggregating results.
  • Can impact consistency and fault tolerance depending on the implementation.

Common pitfall: Not mentioning the need for query routing and result aggregation across shards.

13. What is hybrid search?

  • Combines vector similarity search (semantic) with traditional keyword or BM25 search (lexical).
  • Aims to leverage the strengths of both approaches for improved search relevance.
  • Results from different search types are typically ranked and merged using a fusion algorithm.
  • Useful when exact keyword matches are important alongside semantic understanding.

Common pitfall: Confusing it with just using multiple embedding models or failing to mention result fusion.

14. How do you choose between a dedicated vector database and using pgvector?

  • Dedicated vector DBs often offer higher performance, scalability, and advanced ANN features.
  • pgvector provides a convenient way to add vector search to existing PostgreSQL applications.
  • Considerations include dataset size, query latency requirements, operational complexity, and existing infrastructure.
  • pgvector might be sufficient for smaller datasets or simpler use cases where integration is key.

Common pitfall: Not acknowledging the trade-offs in performance and feature set between the two options.

15. How do you evaluate the performance of a vector database?

  • Measure recall (percentage of true nearest neighbors found) at different query latencies.
  • Benchmark throughput (queries per second) under various load conditions.
  • Analyze index build time and memory/disk usage.
  • Consider the impact of metadata filtering and update/delete operations.

Common pitfall: Focusing solely on latency without mentioning recall or throughput.

16. What are the failure modes for ANN search?

  • Low recall: Failing to find true nearest neighbors due to the approximate nature of the search.
  • High latency under load: Performance degradation when query volume exceeds system capacity.
  • Index corruption: Issues during index building or saving/loading leading to unusable indexes.
  • Inaccurate results due to poor embedding quality or inappropriate distance metric choice.

Common pitfall: Only mentioning low recall and not considering operational or data quality issues.

FAQ

What is the most important concept to understand for vector database interviews?

Understanding the trade-off between search accuracy (recall) and speed (latency) inherent in Approximate Nearest Neighbor (ANN) search is crucial. Knowing how different indexing strategies manage this trade-off is key.

How can I practice for these questions?

Implement a small-scale vector search system using libraries like Faiss or Annoy, experiment with different indexes and parameters, and read documentation for popular vector databases.

Should I memorize specific algorithms?

Focus on understanding the core principles, mechanisms, and trade-offs of major algorithms like HNSW and IVF, rather than rote memorization. Be able to explain how they work conceptually.

What level of detail is expected for indexing algorithms?

Be prepared to explain the high-level approach (e.g., graph-based, partitioning-based), key parameters, and the resulting performance characteristics. Deep mathematical derivations are usually not required unless specified.
